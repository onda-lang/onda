# Runtime and codegen measurements — 2026-10-23

This report consolidates the runtime audit, implementation batches, and the intervening codegen
review. It records historical measurements; current design lives in
[compiler architecture](../../../docs/architecture.md#optimization-boundaries) and
[the MIR contract](../../../docs/mir.md#backend-neutral-passes).

LLVM is the primary target. Shared proofs and simplifications belong in MIR; target cost models
choose vector widths and instruction schedules. These experiments retained strict floating-point
permissions. Results apply to the measured workloads and do not establish universal performance.

The original audit used revision `c1df539c2c68326cc61414121e1bd5051aa56cfb` on an Intel Core
i9-14900HX, Linux x86-64, LLVM 21.1.2, host AVX2/FMA targeting, 48 kHz, and 128-frame blocks.
The first implementation was measured on logical CPU 2; the second used CPU 6 to avoid sharing a
physical core with concurrent tests. Compare before/after pairs within each batch, not absolute
numbers across batches. The raw evidence records tool versions and source/worker identities.
The machine had no exclusive core reservation or controlled clock frequency. Small differences
need repeated confirmation. The first two batches collected no hardware counters; the optimization
follow-up below adds counter measurements.

Times are nanoseconds per audio frame unless explicitly labeled per transform. A block transforming 512 elements or running an FFT still
has its complete work divided by the host block size. Compilation, initialization, and capture I/O
are outside steady-state timing. Raw-ABI microkernels and wrapper-inclusive examples have different
overheads; neither measures complete browser or device-callback latency.

## Implemented changes

| Area | Retained change |
| --- | --- |
| MIR bounds | Nonwrapping affine slice indices and conservative division, remainder, mask, and shift ranges remove proven checks. |
| MIR memory | Interprocedural storage origins preserve object identity; LLVM uses them for scoped aliasing and complete-object alignment. |
| MIR loop legality | Pointwise audio proofs survive pure scalar value-only helpers that cannot fail or have unproved termination. LLVM guards disjoint/exactly equal buffers; partial overlap stays ordered. |
| MIR scheduling | Fixed loops of at least 32 iterations may separate expensive independent rendering from an ordered sum over already materialized values, without scratch arrays. |
| Standard library | OnePole, DecayEnv, and Pan3db cache coefficients at parameter updates; polyphonic_saw uses one cached panner per voice. |
| LLVM math | A late resolver maps supported optimizer-created vector exp2 intrinsics to bundled SLEEF, preserving application flags and strict helper arithmetic. |
| Wasm SIMD | Interface-control loads (`param`) are recognized as invariant in eligible straight-line sample loops. |

Panner validation also exposed and fixed tuple state-destination rewriting, recursive generic-proc
constructor traversal, and premature validation of generic struct-array arguments in the proc pass.
These are correctness fixes; no separate throughput gain is attributed to them.

The distributed voice probes are **3.9–5.4× faster on LLVM**, with a **4–8% Wasm regression**.
That tradeoff is accepted under the LLVM-first priority. The nine example captures are bitwise
unchanged before/after within each backend, at startup and after warmup. Distributed native sine
probes differ by at most `1.79e-7` because they now use SLEEF vector math instead of scalar libm;
their Wasm captures remain bitwise equal. A cancellation-sensitive fixture verifies the retained
addition order.

Three alternating before/after raw-ABI process pairs, each with seven rounds, confirm the in-place

regresses **0.428 → 0.486**. The additional guard has a measurable cost on short overlapping calls.
These raw-ABI figures are distinct from the ordinary runner's wrapper-inclusive audio-map timing.

work, so the throughput and numerical results above are the acceptance evidence.

## Findings after the second implementation

The short-slice and FFT findings below motivated the [optimization follow-up](#optimization-follow-up).
That section records their resolution and the limits that remain.

- The five-element `slice-derived-bounds` stress fixture regressed on native: the full sweep was
  **7.725 → 12.079 ns/frame**. A stage comparison measured **7.518 baseline, 7.577 bounds-only,
  11.117 with memory facts, and 10.959 final**. This isolates the regression to memory-fact lowering,
  rather than loop distribution; its exact scheduling cause remains unresolved. An explicit small
  trip cap did not recover the baseline. Keep it in future alias/alignment comparisons.
- FFT throughput improvement is unproved. The initial C/FFTW comparison measured Onda/reference
  ratios of **1.78×** at 1,024 points and **1.66×** at 4,096 points, with unequal timed wrapper work
  and a selected-bin reference check. Match timed work and validate the complete transform before
  attributing the gap to bounds, alignment, layout, or algorithm choice. Full-spectrum DFT accuracy
  fixtures at 256 and 512 points pass in both precisions on both backends. A first-sweep f64 4,096-point
  slowdown did not recur consistently in three paired runs: 46.337/45.879, 45.394/45.137, and
  45.518/47.636 ns/frame.
- `additive_synth` and `fdn_reverb` already exceed the harness's default native/Wasm tolerance after
  warmup with the baseline compiler. Old/new captures within each backend remain the appropriate
  transformation check; separate parity fixtures retain explicit exact/approximate contracts.
- External-asset runtime and cache behavior for `embedded_room` and the buffer-backed `sample_player`
  remain unmeasured. They compile and emit artifacts, but a stopped player is not a useful workload.
- General persistent expression caching, selected state promotion, offset-aware memory facts,
  broader Wasm vectorization, vector sin/cos fusion, failure-branch layout, and FFT/locality tuning
  need isolated evidence. Ordinary scalar sin/cos already fuses to sincosf on the inspected x86
  target. Do not infer missing optimization from pre-optimization IR or vector types alone.

The [previous cleanup evidence](2026-10-22.json) records rejected broad memory CSE, forced constant
alignment, and FFT padding. Earlier portable pre-inlining regressed a larger reverb by about 30%.
Promoting all 33 oversampling scalars more than doubled object size; that growth alone is not grounds
for rejecting the transform. Further inlining and wider promotion should be judged by measured
runtime performance, including throughput and callback latency, with no generated-code size limit.

## Optimization follow-up

The three follow-up areas were the unresolved short-slice regression, insufficient FFT/locality
measurement, and uneven optimization coverage. Most new compiler logic is shared MIR analysis;
native lowering consumes its results without changing strict floating-point permissions.

**Short slices.** The minimized reverse-copy loop exposed LLVM 21's masked AVX2 memory costs.
Adding valid bounds alone did not recover performance; disabling loop vectorization for this small
copy did. MIR now propagates descriptor length caps through call chains, and a native profitability
policy keeps cheap copies of fewer than eight elements scalar on AVX2 targets without AVX-512.
The policy leaves arithmetic kernels and larger copies to LLVM; alias and alignment facts remain.
The original two-helper fixture improved **11.419 → 7.414 ns/frame**, **35.1% less time**, in three
alternating process pairs with seven 60 ms rounds. A separate comparison with the historical
pre-regression worker measured **7.875 → 7.425**. All error outputs were zero.

A two-pair sweep covered f32/f64 capacities 1, 2, 3, 4, 5, 7, 8, 9, 16, 64 and 512 with independently
varying lengths, including empty slices. Capacities 2–7 took **14.5–36.7% less time**. Capacities
1 and 8–512 stayed within 1.7% of the baseline. An initial eight-element scalar preference was
removed after measurement. These are host-specific cost decisions, not new language semantics.

**Complete FFTs and locality.** The new [FFT harness](../README.md#complete-ffts-and-cache-pressure)
compares the same observable operation: N immutable real samples to all N/2+1 positive-frequency
complex bins. It includes Onda's publication loop and excludes planning, allocation, initialization
and validation. Every bin is checked against FFTW for eight input patterns and for every instance.
Split-plane spacing and alignment are consistent across FFTW new-array executions. Old/new Onda
output fingerprints match throughout. Independent full-spectrum DFT and forward/inverse checks
also pass at 256 and 512 points in both precisions on native and Wasm.

MIR now proves independence of affine array accesses through straight-line helper calls, including
the mirrored-bin reconstruction loop. LLVM consumes the proof using access groups, which survive
inlining and debug-info loop-ID replacement. A diagnostic that only requested vectorization still
failed; supplying the dependence proof enabled it. No FFT-specific compiler pattern is used.

The table shows medians of three alternating before/after process pairs, seven 40 ms rounds each,
on CPU 6. Units are **nanoseconds per complete transform**. The raw evidence also includes 32
instances and all FFTW rounds; clocks remained uncontrolled.

| f32 | 1,024 | 1 | 1,205.4 | 961.9 | 1.11 |
| f32 | 1,024 | 512 | 1,444.6 | 1,156.6 | 1.30 |
| f64 | 1,024 | 1 | 1,633.7 | 1,331.4 | 1.43 |
| f64 | 1,024 | 512 | 1,994.6 | 1,733.0 | 1.59 |
| f32 | 4,096 | 1 | 5,513.1 | 4,308.7 | 1.19 |

Across all twelve cases, elapsed time falls **11.6–21.8%**. Hardware counters measured separately
show about **25% fewer instructions for f32** and **18–19% fewer for f64**. Cache misses do not
consistently decline: this is an instruction-efficiency gain. Large f64 working sets still incur
more last-level cache misses and higher latency. FFTW remains faster; these results do not establish
state-of-the-art FFT throughput or a general cache-locality improvement.

**Coverage and correctness.** The same MIR proof handles `for` and `while`, forward/reverse affine
addresses, fixed windows and nested straight-line helpers. It rejects overlapping iterations,
wrapping intermediates, unknown scalar borrows, unresolved origins, recursion and unsupported
control flow. Reference tests include a scalar borrow that observes an earlier iteration's array
write. Counted-loop recognition is shared with loop distribution. Descriptor length tests cover
forwarding, multiple call sites and unknown external lengths. LLVM metadata construction also uses
temporary nodes safely before resolving cycles.

All nine example startup/warmed captures remain bit-identical within each backend; their Wasm
binaries are byte-identical. The example sweep shows no material native regression, but is not
used to claim small gains. Preserved workers predate the earlier annotation cleanup in six embedded
stdlib modules, which explains changed source fingerprints. The FFT body is unchanged apart from
one redundant boolean annotation in that embedded snapshot.

Final checks pass: **332 MIR/native checks including the doctest**, **1,085 semantic tests**,
**104 JavaScript tests**, **44 Wasm corpus fixtures**, **42 parity scenarios × two Binaryen
configurations**, and **11 benchmark tests including integration**. The timeout test now waits for
a killed descendant to exit, removing a scheduling race in its assertion. No authored source file
exceeds 5,000 lines. Scratch artifacts are under `target/bench/optimization-followup/`.

General persistent caching, wider state promotion, unresolved view/alias cases and external-asset
workloads remain separate measured-work items. This batch adds reusable proofs and fixes the
demonstrated regression; it does not replace those remaining investigations with blanket transforms.

## General array and state access

The next batch targets shared compiler behavior across programs. MIR's interval and path-sensitive
bounds proofs now use the same traversal of fixed arrays, state projections, constant tables,
interface arrays, reference windows, collection selectors and slices. Boolean branch joins preserve
short-circuit guard implications. A guarded, otherwise unmodified `i32` unit-step counter retains
its initial lower bound because the exclusive comparison prevents increment overflow. Mutation,
unproved arithmetic and other loop shapes remain conservative.

The shared dependence analysis also proves disjoint stride residue classes, such as interleaved
even/odd elements. Helpers can receive any of several complete owned state arrays; intersecting
origin sets still retain their possible aliasing. Neither change requires MIR inlining or new
floating-point permissions. LLVM consumes the existing dependence metadata interface.

The new `array-guarded-{helper,state}-{f32,f64}` workloads perform the same forward/reverse map over
a runtime-sized prefix of 512 elements. Native assembly replaces clamped gathers with contiguous
vector memory operations. Four additional bounds operations disappear in MIR for each workload.

## Generic state views and descriptor shapes

MIR now preserves constant contiguous offsets and extents through state-backed views, helper
parameters and returns. Facts join all definitions and call sites; conflicting ranges lose their
precision while retaining storage identity. This enables three shared improvements:

- Fold known descriptor lengths and remove proven construction, element and fixed-window checks.
  Fixed windows still require a contiguous payload of sufficient size, including when the index
  alone is already proven safe.
- Prove independence between regions of the same array using absolute logical element offsets.
  The proof covers fixed references and known-shape slice descriptors, including descriptors
  formed before the loop. Overlapping and unresolved views retain their dependencies.
- Preserve reference alignment through offset views. LLVM converts logical offsets using its
  physical layout; a one-element f32 offset receives 4-byte alignment, while a sixteen-element
  offset into a 64-byte-aligned array retains 64-byte alignment.

The new `state-window-{array,slice}-{f32,f64}` probes map 256 elements between separate regions
of one 1,024-element state array. LLVM previously kept these loops scalar. MIR's dependence proof
now permits contiguous SIMD accesses. In the slice variant, five runtime length queries disappear
from MIR. Simple inlined offsets already recovered native alignment before this change; the
measured speedup here comes from exposing independence between views of the same object.

## Shared views and bounded runtime loops

MIR now retains alternative contiguous views of the same state object across helper calls.
Common lengths survive differing offsets, allowing descriptor cleanup, bounds proofs and loop
dependence analysis to use the joined facts. Native reference alignment holds for every possible
offset. Overlapping alternatives retain their aliasing; a finite analysis budget bounds growing
view sets and falls back conservatively. Calls continue to share one MIR helper.

The dependence proof also accepts runtime `i32` loop limits with a known upper bound. It checks
the full possible iteration range and retains the counter's non-wrapping unit-step requirement.
Integer `min` and `max` now retain one-sided bounds when the other operand is unconstrained,
so ordinary `min(max(count, 0), capacity)` loops benefit without a ranged parameter annotation.

All six new probes change from scalar processing loops to SIMD in optimized native IR. The
shared slice variants additionally remove three remaining `SliceLen` queries from MIR.

## Reproduction

Follow the [benchmark harness guide](../README.md) for builds, settings, parity, reference kernels,
and inspection. A representative example comparison is:

```sh
cargo build --release -j1 -p onda_examples --features llvm-orc --example benchmark_dsp
export PATH="$PWD/.deps/llvm-src/21.1.2-static/bin:$PATH"
python3 scripts/bench/run.py \
  --source examples/basic/polyphonic_saw.onda \
  --source examples/spectral/spectral_freeze.onda \
  --backend both --ir --assembly --remarks \
  --repetitions 7 --round-ms 50 --block-size 128 --cpu 2 \
  --memory-mib 4096 --timeout-seconds 120 \
  --output target/bench/runtime-comparison
```

Build a separate baseline worker and use matching source/settings for before/after claims. The
JSON files retain diagnostic source strings, experiment transformations, and raw-ABI harnesses;
the ordinary runner does not vary payload aliasing. Manually changed unchecked MIR requires the
recorded proof and exact transformation, not a general bypass of validation.

Ignored scratch artifacts were kept under `target/bench/runtime-audit-2026-10-23/`,
`runtime-improvements-2026-10-23/`, `codegen-stack-review-2026-10-23/`, and
`codegen-fixes-2026-10-23/`. They include MIR, pre/post optimization LLVM, objects, WAT, assembly,
remarks, and captures, and must be regenerated on another checkout. CPU-2 pilot timings from the
second implementation shared a physical core with semantic tests and were excluded.

Future comparisons should cover x86-64/AArch64, f32/f64, short and event-delimited segments,
disjoint/in-place/overlapping buffers, hot/cold working sets, multiple instances, realistic assets,
long feedback trajectories, nonfinite inputs, and scalar/vector tails. Report callback latency
and code size as well as mean throughput; use hardware counters before making cache claims.
